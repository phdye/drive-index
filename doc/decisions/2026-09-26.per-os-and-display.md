# A per-OS layer, a default label, and trimmed output

Accepted 2026-09-26. Proposals: `doc/proposal/per-os-layer.md`,
`doc/proposal/smaller-gaps.md`.
Classification: two-way door — three config keys and a lookup tier, with no
stored state and nothing to migrate.

## The per-OS layer

`[os.<name>]` sits between `[defaults]` and `[drive.<label>]`, so a label's
own setting still wins. `<name>` is the normalized system name, and
`DRIVE_INDEX_OS` overrides it — which is also what lets the bar exercise a
system it is not running on.

`locate` and `updatedb` are now settings rather than whatever `PATH` finds.
That is the half with teeth: the project declares a Python 3.6 floor
specifically so it can run on two systems, and that floor is pointless if the
configuration cannot describe both. A configured binary that does not exist
fails with the value, the key and the file it came from, rather than as an
errno from inside `subprocess`.

Not done: per-label tool overrides. An imported index built by mlocate rather
than findutils would need a different `locate` to read it, and the two
formats are not compatible. The lookup already walks a section list, so this
is a one-line change if that case ever arises — and inventing it before it
does would be inventing a requirement.

## `default_drive`

Unset, a bare `drive-index locate foo` is a usage error naming the option
that would fix it.

That is the decision worth recording, because the alternative is tempting.
Defaulting to the drive holding the current directory, or to every index
held, would both make the bare form work — and both would search one thing
while the caller believed they had searched another. The whole design already
turns on that asymmetry: widening is safe, narrowing misleads, and a guess is
narrowing in disguise. Refusing costs one line of config, once.

It may name a group, since a group is only an indirection to labels, and the
group's own selectors still narrow it.

## `trim_prefix`

Strips a prefix from reported paths and changes nothing else. The index keeps
the full path, so `--existing` still resolves and a reported hit can still be
opened; only what is printed changes. Indexing a tree through an installation
root otherwise reports paths that are correct and unusable.

Two consequences fall out of doing it at display time:

It cannot apply to `-c`, `-0` or `-S`, where `locate` emits something other
than one path per line. That is said at normal verbosity rather than silently
skipped, because a trim that quietly stopped happening is worse than one that
never did.

Searching several indexes at once means a hit cannot be attributed to the
index it came from, so every participating prefix is tried and the longest
match wins. That is right where roots are distinct, which they are in every
arrangement this supports. A `trim_prefix` that would strip an unrelated
path is a configuration mistake and not something this can detect.

## One defect found while building

The verbosity level is computed from the label, and `default_drive` resolves
the label — so the line reporting which default was used was emitted while
the reporter still sat at its default level, and `-v` never showed it. It is
reported after the level is settled now.

The general shape is worth keeping: anything reported while working out what
to report against is measured with a yardstick that does not exist yet.

## Not code

`doc/proposal/smaller-gaps.md` also carries the fixed mount-point project.
That is an operator change — attaching volumes at stable paths rather than
whatever letter is handed out — and no code here can do it. It stays in the
proposal, and the `volume` guard exists to catch the case it removes.
